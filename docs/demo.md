# Тестові дані StudHub

Демо-набір додано до локальної робочої бази. Групи мають префікс `[Демо]`.
Для поточного наявного акаунта вони доступні через перемикач простору або `/groups/`;
власні групи та особисті дані збережені.

| Email | Роль у `[Демо] ПМНБ-26-1` | Що перевіряти |
| --- | --- | --- |
| `owner@studhub.test` | Староста | Всі дії, права, заявки, аналітика |
| `deputy@studhub.test` | Заступник | Створення завдань і навчальний план; без зміни ролей |
| `student@studhub.test` | Студент | Особисті статуси, коментарі, файли; без редагування завдань |
| `applicant@studhub.test` | Очікує вступу | Заявка й відсутність доступу до групи до схвалення |
| `guest@studhub.test` | Поки немає груп | Порожній стан і власна заявка |

Пароль усіх нових демо-акаунтів: `StudHub-demo-2026!`.
Це окремі тестові акаунти без прав адміністратора Django.

Дані включають дві групи, шість семестрів, 15 предметів, 48 завдань,
чотири персональні статуси, прострочені та майбутні дедлайни, коментарі,
завантажуваний текстовий файл, сповіщення, запрошення та заявки на вступ.
В IT Community староста — демо-заступник, а демо-студент є заступником:
це дозволяє перевірити незалежність ролей у різних групах.

## Повторне наповнення

```bash
uv run python manage.py seed_demo
```

Щоб надати існуючому акаунту доступ до демо-груп:

```bash
uv run python manage.py seed_demo --attach-user-id 1
```

Команда доступна лише з `DEBUG=True`. Повторний запуск зберігає існуючі
записи, паролі й внесені зміни та додає відсутні дані. Перед першим
наповненням робочої бази створено SQLite-копію в `/tmp/studhub-before-demo-*.sqlite3`.

## Профіль і вихід

Натисніть «Мій профіль» унизу бічної панелі. Меню містить «Налаштування»
та «Вийти з акаунту». Вихід виконується POST із CSRF, меню закривається
кліком поза ним або Escape. Меню працює і зі згорнутою навігацією.
На сторінці налаштувань залишені особисті дані й безпека без зайвої панелі вкладок.
