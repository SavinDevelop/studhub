# StudHub: модель даних за Figma

Джерело: [StudHub — UI/UX Design](https://www.figma.com/design/riA4v6ELtxnYnfVgOL7gbR/StudHub?node-id=66-23),
сторінка `04 · Desktop — Interactive Prototype`. Аналіз охоплює основні сценарії
студента, заступника та старости, навчальний план і архівні семестри.

## Зв'язки та правила

- `User → GroupMembership → StudyGroup`: кілька груп, унікальна пара користувач/група.
  `StudyGroup.owner` залишається джерелом ролі старости; власник має також членство.
  Ролі `student` та `deputy` не дублюють власника і можуть відрізнятися в різних групах.
- `StudyGroup → Semester → Subject → Topic`. Завдання належить предмету; його
  група й семестр визначаються через предмет, без дублювання зовнішніх ключів.
  Тема необов'язкова й повинна належати цьому ж предмету.
- Для кожної групи може бути тільки один поточний семестр, що забезпечено
  умовним унікальним обмеженням БД. Старий семестр можна зробити поточним;
  дані інших періодів зберігаються. Дата завершення не раніше початку.
- Курс — 1–4 відповідно до CoursePicker `150:265`. Навчальний рік зберігається
  як початковий рік семестру (`2026` → `2026 / 2027`), щоб архіви не залежали
  від поточного календарного року. Контакти викладача належать предмету;
  окремого облікового запису викладача макет не передбачає.
- `TaskProgress` має унікальну пару завдання/студент і чотири стани:
  `not_started`, `in_progress`, `completed`, `graded`. Відсутність запису
  означає «Не виконано». «Оцінено» в макеті — самостійно обраний стан;
  числові оцінки, перевірку викладачем і журнали оцінок не додано.
  Прострочення визначається з дедлайну та особистого стану, не зберігається.
- `TaskAttachment` містить рівно одне джерело: файл або HTTP(S)-посилання.
  `SubmissionLink` збережено для окремих посилань на здачу роботи.
- Коментарі належать завданню, мають автора й згадки учасників групи.
  Сервіс не дозволяє коментувати чужу групу або згадувати сторонніх користувачів.
- Ліміт запрошення за замовчуванням — 20 заявок. Нова або повторна після
  відхилення заявка використовує одне місце; повторний POST очікуваної заявки
  не збільшує лічильник. Схвалення вже створеної заявки можливе після вичерпання
  ліміту. Раніше створені запрошення рахують використання з моменту цієї міграції.
  Email-запрошення приймає тільки користувач із відповідним підтвердженим email у allauth.
- Права на завдання, навчальний план та аналітику доповнюють чинні групові права.
  Староста має всі права. Заступнику за замовчуванням доступні завдання й
  навчальний план; існуючі дозволи на запрошення/заявки збережено.
  Зміна політики однієї групи не впливає на інші.

## Міграція наявних завдань

Початкові `Task.subject` і `Task.topic` були текстом, без групи та семестру.
Міграція **перейменовує**, а не видаляє їх у `legacy_subject` і `legacy_topic`.
Нові зв'язки `subject`/`topic` залишаються порожніми для старих рядків:
визначати групу за назвою предмета недостовірно. Адміністратор має прив'язати
такі завдання до потрібного предмета та за потреби теми через Django admin.
Нові завдання через сервіс потребують предмета. Старі завдання без прив'язки
не доступні сервісам особистого прогресу та коментарів.

API `tasks.services.create_task` тепер приймає об'єкт `Subject` і необов'язковий
об'єкт `Topic`, замість текстових назв. `list_tasks(subject=...)` підтримує
як об'єкт, так і назву для пошуку. Низькорівневий CRUD `create_task`,
`update_task`, `get_task`, `list_tasks`, `delete_task` залишається внутрішнім:
авторизацію має виконувати викликаючий код. Для створення з перевіркою прав
є `create_group_task(user, ...)`. Майбутні views повинні використовувати
групові перевірки для кожної операції. HTTP-маршрути та перевірки доступу описані нижче.

## Інтерфейс і стилі

Інтерфейс відтворено Django-шаблонами за Figma, зі спільними partials у
`templates/ui/`. Токени й адаптивна верстка зберігаються в `assets/css/app.css`,
поведінка меню, діалогів і форм — у `assets/js/app.js`. Локальні іконки Lucide з ліцензією — у `assets/icons/lucide/`;
логотипи з Figma — у `assets/figma/`, шрифт Geist із ліцензією — у `assets/fonts/`.
Іконки успадковують колір тексту; CSS та JS мають версію URL для оновлення кешу.
Зовнішні тимчасові Figma URL не використовуються в HTML.

daisyUI та `django-tailwind-cli` видалені з залежностей і налаштувань,
згенеровані старі CSS прибрані. Інтерфейс працює без Node.js або CSS-збірки.

## Сторінки

| URL | Можливості |
| --- | --- |
| `/` | Головна сторінка з макета |
| `/accounts/login/`, `/accounts/signup/`, `/accounts/password/reset/` | Вхід, реєстрація, Google OAuth, відновлення пароля |
| `/profile/` | Перший вхід, ім'я/прізвище, аватар із попереднім переглядом |
| `/dashboard/` | Особисті показники, дедлайни, прогрес, вибір групи |
| `/tasks/`, `/tasks/?view=table` | Одна сторінка з вкладками списку й таблиці; пошук, фільтри всіх пріоритетів, сортування, пагінація та власні статуси. Старий `/tasks/table/` перенаправляє зі збереженням фільтрів |
| `/tasks/new/`, `/tasks/<id>/edit/` | Необов’язкова дата початку, введення теми текстом, три пріоритети, кілька файлів до 10 МБ кожен та окремі рядки посилань на матеріали й здачу |
| `/tasks/<id>/` | Опис, захищені вкладення, коментарі, особистий прогрес |
| `/calendar/` | Дедлайни доступних груп, навігація між місяцями |
| `/subjects/` | Предмети семестру, контакти, прогрес, архів |
| `/groups/<id>/academic/` | Навчальний план: курс, створення/редагування/активація семестрів і керування предметами. Рік не потрібно вводити, завершення семестру необов’язкове |
| `/subjects/new/`, `/subjects/<id>/edit/` | Предмет, контакти викладача, додавання тем |
| `/semesters/` | Сумісність зі старими посиланнями: перенаправлення на навчальний план |
| `/groups/` | Групи, перехід за запрошенням, власні заявки |
| `/groups/<id>/` | Учасники, пошук, фільтр ролей, профілі, призначення ролей, заявки |
| `/groups/<id>/settings/` | Загальні налаштування групи |
| `/groups/<id>/permissions/` | Дозволи ролей, доступні старості |
| `/groups/<id>/invitations/manage/` | Загальні/іменні запрошення, копіювання, відкликання |
| `/analytics/`, `/matrix/` | Реальна статистика, матриця статусів, фільтри та CSV |
| `/notifications/` | Особисті сповіщення, непрочитані, позначення прочитаними |
| `/settings/account/` | Адаптивні блоки профілю й безпеки, аватар, заблокована поточна пошта, пароль і Google OAuth |
| `/settings/account/email/`, `/accounts/email/` | Зміна пошти з модального вікна; allauth надсилає підтвердження, і тільки підтверджена нова адреса замінює поточну. Ручне призначення непідтвердженої основної адреси заборонено |

Вибрані група й семестр зберігаються в сесії; бічне меню можна згортати,
на мобільному воно відкривається як панель. Усі зміни виконуються POST із
CSRF, а права перевіряються на сервері. Вкладення доступні тільки через
перевірений маршрут `/tasks/<id>/attachments/<id>/`; локальний медіамаршрут
роздає лише аватари. У production вкладення також не можна публічно роздавати
через MEDIA_URL — потрібна така сама перевірка доступу.

HTTP-створення та редагування завдання породжує персональні сповіщення
іншим учасникам групи. Іменні запрошення створюють посилання для передачі
адресату; автоматичну email-розсилку й планувальник нагадувань не ввімкнено.
Кнопка в UI чесно називає цю дію створенням запрошення. Числових оцінок
і непідтверджених налаштувань сповіщень не додано.

Демонстраційні дані для перевірки браузером створювалися в окремій базі
у `/tmp`; робоча база не заповнювалася вигаданими завданнями.

Розділи групи відкриваються з бічної навігації без вкладок на сторінках
учасників і навчального плану. Пункти меню відображаються за правами групи;
прокручується лише область посилань, кнопка профілю залишається внизу.


Системні повідомлення відображаються справа вгорі поверх інтерфейсу,
з анімацією та кнопкою закриття. Автоматичне приховування призупиняється
при наведенні, фокусі клавіатури та в неактивній вкладці.

Налаштування `core/settings.py` призначені для локальної розробки (`DEBUG=True`,
консольна пошта). Перед розгортанням потрібні окремі production-налаштування,
приватний `SECRET_KEY`, дозволені хости, HTTPS і поштовий backend.
